Authentication

All requests require a token. Obtain one by exchanging credentials at the token endpoint.

POST /registry/api/token-auth/ Obtain API Token
curl -X POST {{ request.scheme }}://{{ request.get_host }}/registry/api/token-auth/ \ -H "Content-Type: application/json" \ -d '{"username": "your_user", "password": "your_pass"}'
import requests resp = requests.post( "{{ request.scheme }}://{{ request.get_host }}/registry/api/token-auth/", json={"username": "your_user", "password": "your_pass"} ) token = resp.json()["token"]
const resp = await fetch("{{ request.scheme }}://{{ request.get_host }}/registry/api/token-auth/", { method: "POST", headers: { "Content-Type": "application/json" }, body: JSON.stringify({ username: "your_user", password: "your_pass" }) }); const { token } = await resp.json();
Response:
{"token": "9944b09199c62bcf9418ad846dd0e4bbdfc6ee4b"}
Use in all subsequent requests:
Authorization: Token 9944b09199c62bcf9418ad846dd0e4bbdfc6ee4b
AI Agent Integration Guide
NEW

RIFTS-X is architected for programmatic orchestration by LLM-based agents (LangChain, AutoGen, CrewAI, OpenAI function-calling, Gemini tool-use etc.).

1. Token in every call

Set Authorization: Token <token> in every HTTP tool call. Store it in agent memory or environment variables.

2. Workflow Polling

GET /api/requisitions/ or /api/brds/ periodically to detect state changes and pending items requiring action.

3. Signature Payloads

Signing endpoints expect: "signature_data": "data:image/png;base64,...". Generate a synthetic or blank PNG for automated approvals.

4. BRD Quorum Logic

BRD approval flows: PMT → HOD → Board. Check current_level and approval_status before each POST to /brds/{id}/sign/.

Supply Requisitions

GET /registry/api/requisitions/ List requisitions (scoped by role)

Results auto-scoped by role. Superusers see all. Includes nested items, quotations, and signatories.

curl {{ request.scheme }}://{{ request.get_host }}/registry/api/requisitions/ \ -H "Authorization: Token YOUR_TOKEN"
POST /registry/api/requisitions/{id}/sign/ Sign / Approve / Reject

Advances the 7-stage approval workflow. System validates caller's role against expected stage signatory.

curl -X POST {{ request.scheme }}://{{ request.get_host }}/registry/api/requisitions/5/sign/ \ -H "Authorization: Token YOUR_TOKEN" \ -H "Content-Type: application/json" \ -d '{"action":"approve","signature_data":"data:image/png;base64,iVBORw..."}'
curl -X POST {{ request.scheme }}://{{ request.get_host }}/registry/api/requisitions/5/sign/ \ -H "Authorization: Token YOUR_TOKEN" \ -H "Content-Type: application/json" \ -d '{"action":"reject","rejection_reason":"Budget limit exceeded."}'
curl -X POST {{ request.scheme }}://{{ request.get_host }}/registry/api/requisitions/5/sign/ \ -H "Authorization: Token YOUR_TOKEN" \ -H "Content-Type: application/json" \ -d '{ "action": "approve", "signature_data": "data:image/png;base64,...", "bid_analysis": "Supplier A is most competitive.", "quotations": [ {"supplier_name":"Supplier A","quoted_amount":4500,"is_chosen":true}, {"supplier_name":"Supplier B","quoted_amount":5100,"is_chosen":false} ] }'

Business Requirement Documents

GET/api/brds/

List all BRDs with approval status

POST/api/brds/

Create a new BRD

POST /registry/api/brds/{id}/sign/ Sign BRD — PMT / HOD / Board

3-level quorum: PMT → HODs → Board. Once each level's quorum is met, it auto-advances.

curl -X POST {{ request.scheme }}://{{ request.get_host }}/registry/api/brds/3/sign/ \ -H "Authorization: Token YOUR_TOKEN" \ -H "Content-Type: application/json" \ -d '{"action":"approve","signature_data":"data:image/png;base64,..."}'
Response:
{"status":"approved","brd_status":"Approved","message":"BRD fully approved by all quorums."}
