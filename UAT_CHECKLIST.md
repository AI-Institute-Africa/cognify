# Cognify BRD Change Request — UAT Checklist

Source: `Cognify_Business_Requirements_and_Change_Request.docx` v1.0 (06 Oct 2026), section 12 Acceptance Criteria. One row per acceptance criterion. Sign off each row after manually exercising it against a running `uvicorn server:app` instance (see the implementation plan's Verification section for why `server:app`, not `main:app`).

| ID | Acceptance Criterion | Steps | Sign-off |
|----|----|----|----|
| AC-01 | A new user can register with a phone number without entering an email address. | Call `POST /api/auth/phone/send-otp` with a phone number, retrieve the code (dev/test channel), call `POST /api/auth/phone/verify-otp`, then `POST /api/auth/register-whatsapp` with the verified phone + password + full name. Confirm the returned user has no email and `phone_verified: true`. | ☐ |
| AC-02 | The user receives an SMS OTP and cannot become phone-verified without successful OTP validation. | Attempt `POST /auth/register-whatsapp` for a phone number that has **not** been verified yet — confirm it is rejected (400, "Phone number not verified"). ## Known gaps / deferred (flag to business owner before go-live)

These were explicitly out of scope for this change request and should be reviewed, not silently assumed complete:

- **FR-21 to FR-29 (exam/assignment backend gating beyond listings)**: this change fixed the previously-dead enrollment gate for course content and the assignments *listing* endpoint, and built the full payment-status/eligibility engine those checks now use. It did **not** add equivalent checks to the exam listing endpoint or to assignment/exam **submission** endpoints — those currently have no payment-eligibility check at all. AC-09 above cannot be fully signed off until this is addressed.
- **FR-01 to FR-05 (full phone-only self-registration)**: only a minimal OTP engine was built, sufficient for WhatsApp registration (section 6.5) and admin-assisted phone verification (section 6.1). General phone-based login/account-recovery was not built.
- **RBAC retrofit**: the ~92 pre-existing inline role checks elsewhere in `backend/server.py` were not converted to the new `require_roles`/`enforce_org_scope` helpers — only new endpoints in this change use them.
- **RIFTS-X / scheduled email reporting (FR-18)**: only an on-demand CSV export (`GET /org-admin/reports/course-pricing`) was built. A scheduled push to `reports@aiinstituteafrica.com` or a RIFTS-X integration needs separate confirmation and build-out.
- **Two backend entry points** (`backend/main.py` vs `backend/server.py`) — pre-existing inconsistency, unrelated to this CR, but worth the team's attention since `main.py` is missing entire feature areas (exams, assignments, all payments) that `server.py` has.
